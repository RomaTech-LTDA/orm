# Changelog

All notable changes to @romatech/orm will be documented in this file.

## [Unreleased]

## [2.1.0] - 2026-11-11

### Security
- `deleteWhere()` / `updateWhere()` quote the table name with the provider's dialect (new optional `IDbProvider.quoteIdentifier()`), or as an escaped ANSI identifier when the provider has none; a `"` in the name can no longer close the identifier and inject SQL. `whereClause` / `setClause` remain raw SQL by design (documented).
- Scaffold: table and column names read from the database are escaped in the generated TypeScript and can no longer make it write files outside `outputDir` (path traversal) or inject code.
- `downgradeDatabase()` only reverts migrations whose file exists in `migrationsPath`; a name read from the history table that is not a migration file (e.g. `../../x`) is rejected before anything runs.

### Fixed
- **The SQL `WHERE` never drops rows the JavaScript predicate accepts.** The providers re-apply the predicate in memory, so the server filter may be wider but never narrower. These are no longer translated (they run in memory):
  - block bodies with more than one statement (only the first `return` used to be translated) and lambdas without a parameter (outer variables were treated as columns);
  - bare members of properties that are not known to be boolean (`u => u.name` became `name = true`: a type error on SQL Server/PostgreSQL, fewer rows on MySQL);
  - string `!==`, `<`, `<=`, `>`, `>=` and every negated `.includes()` / `.startsWith()` / `.endsWith()` (case-insensitive collations and trailing-space padding rejected rows JavaScript accepts);
  - LIKE values containing `\` or `[`, string literals with escapes other than `\'`, `\"`, `\`, `!== undefined`, relational comparisons with `null`/`undefined`/booleans;
  - integer literals beyond `Number.MAX_SAFE_INTEGER` (the parameter was a different number), legacy octal literals (`010`) and nested members (`u.address.city`, `u.name.length`).
- `field !== value` (number/boolean) generates `(field != @p OR field IS NULL)`, `!flag` generates `(flag = false OR flag IS NULL)`, and numeric `<`/`<=`/`>`/`>=` add `OR field IS NULL` when JavaScript accepts `null` (`null < 30` is `true`).
- `@NotMapped` properties are no longer sent by `buildInsertSql()` / `buildUpdateSql()` when the entity is an instance of the decorated class.
- Client-side ordering: equal `Date` values fall through to `thenBy()`, and `null`/`undefined` sort first consistently.
- `all()` evaluates its predicate on entities even after `select()`.
- `Transaction.commit()` / `rollback()` call `commitTransaction()` / `rollbackTransaction()` on providers implementing `ITransactionalProvider` (MongoDB transactions were never committed).
- **Migrations:** `createMigration()` without explicit operations only emits the tables (`createTable`) and columns (`addColumn`) missing from the earlier migration files. In 2.0.0 every generated migration re-created all tables, so reverting it dropped every table.
- Scaffold: invalid names become valid identifiers; class/file names are unique ignoring case (`Users` and `USERS` no longer overwrite each other on Windows/macOS) and never reuse an imported or global name (`Entity`, `DbContext`, `Date`, …) or the context name; colliding property names get a numeric suffix; `DbSet` getters never override `DbContext` members; `contextName` must be a valid identifier.
- The entity registry is shared by every copy of the package in the process (a globally installed CLI now sees the project's entities), and methods/accessors are no longer treated as columns.

### Changed
- `parsePredicate(predicate, options?)` takes `{ booleanFields }`; `QueryBuilder.where()` fills it from the entity metadata (`design:type` `Boolean` or `@Column({ type: 'boolean' })`). Without it, bare members are not translated.
- The `QueryExpression` trees produced for `!flag`, numeric relational comparisons and `!==` can now contain `logical` `or` nodes. Custom providers that consume `whereExpressions` must handle `logical` nodes (already part of the type).
- `createMigration()` without explicit operations rejects with a "No model changes" error and writes no file when nothing changed. Pass `{ up: [], down: [] }` to create an intentionally empty migration.
- Docs: `@SoftDelete` and `QueryFilterRegistry` are metadata / explicit helpers and are **not** applied automatically (the 2.0.0 notes and README said otherwise); README gained "What runs on the database" and "Known limitations" sections (including that `@Column({ name })` is not applied by CRUD or queries) and a warning about migrations generated by 2.0.0.
- Standardized `index.html` landing page (GitHub Pages) with new template: header, hero, quick start, features grid, install command, footer.
- Added unit tests (`npm test`); CI runs on Node 22 and 24 with `npm ci` and read-only permissions; publish workflow uses Node 22 and `npm ci`.
- Dev dependencies: lockfile refreshed (fixes advisories in `brace-expansion`/`glob` dev-only dependencies).

### Upgrade notes
- **Review migrations generated by 2.0.0 before reverting them**: their `down` drops every table of the model, not only the ones they introduced. Remove from `up`/`down` the operations for tables created by earlier migrations.
- If you relied on `createMigration()` succeeding with no model changes, pass explicit operations.

## [2.0.0] - 2026-06-26

### Added
- **Transactions**: `beginTransaction()`, `commit()`, `rollback()`
- **Bulk operations**: `bulkInsert()`, `bulkUpdate()`, `upsert()`
- **Raw SQL**: `rawQuery<T>(sql, params)`, `rawExecute(sql, params)`
- **Batch operations**: `deleteWhere()`, `updateWhere()` (no entity loading)
- **Connection retry**: `withRetryPolicy({ maxRetries, backoff })`
- **Connection pooling**: `withPooling({ min, max, idleTimeoutMs })`
- **@Version decorator**: optimistic concurrency control
- **@Index, @CompositeIndex**: database index declarations
- **@SoftDelete()**: auto-filter deleted entities
- **Composite primary keys**: `@PrimaryKey()` on multiple properties
- **Global query filters**: `QueryFilterRegistry` for multi-tenancy
- **Change tracker**: `ChangeTracker<T>` with dirty field detection
- **Eager loading**: `IncludeBuilder` with `.include().thenInclude()`
- **IDbProvider.ping?()**: health check method
- **IDbProvider.bulkInsert?/bulkUpdate?/upsert?**: optional bulk ops

### Providers
- SQLite provider (`@romatech/orm-providers-sqlite`) — sql.js WASM, zero native deps
- MongoDB provider (`@romatech/orm-providers-mongodb`) — full CRUD + transactions + server-side query translation
